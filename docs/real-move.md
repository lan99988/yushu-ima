# 真实移动：2.2.0

沿用同一私有 Site 和插件。原生 `move_knowledge` 对同一知识库的文件和整个目录进行移动。该操作不创建副本，不调用删除接口。跨知识库暂不开放，因为尚未验证跨库 ID 与内容行为。

## 连接与资源绑定

`ima_begin_connection` → 本次新扫码安装器密封 → `ima_finish_connection` → `ima_verify_connection`。`received` 仅代表接收，`authenticated` 代表真实云端刷新成功。令牌过期但刷新仍有效时，移动入口先刷新一次；失败不重试移动。

`ima_bind_move_workspace(workspace,native_knowledge_base_id)` 仅读取腾讯资源，核对原生返回的库 ID、OpenAPI 的正式绑定库及双方全部 11 个根目录的 ID 与名称。只按同名库无法绑定。绑定同时关联 OpenAPI 账号指纹与本次原生用户指纹；换账号不能沿用旧绑定。

## 预览与执行

`ima_move_preview` 需要稳定 `request_id`、源父目录、目标父目录和最多 20 个同源条目 ID。文件夹会递归核对完整子树，最多 500 条、48 层；超过时停止，不只搬一部分。每个文件均读原文并保存 SHA256 和字节数，无法读原文时不执行。源和目标的路径及子项均由原生接口与 OpenAPI 交叉核对。目标必须是固定分类根或已登记且祖先链完整的目录。一级分类、移动到自身后代、同名、目录编号冲突均拒绝。

宿主向用户说明具体预览。用户已经明确要求该批移动时直接执行，无需重复确认；新建目录仍沿用原有每批具体路径确认流程。

`ima_move_execute(request_id,preview_hash)` 在执行前重新核对不可变预览。先持久保存派发意图，再仅提交一次原生移动。相同请求重放不会再提交；不支持覆盖、合并或重命名解决冲突。真实移动未知期间，同库新增上传和目录创建暂缓。

## 超时、冲突与恢复

`ima_move_reconcile(request_id)` 仅读回原任务位置、文件身份及全部原文，不派发移动。显式 `resume_task:true` 仅连接已记录的原 `task_id` 事件流；没有原任务号或已出现同名冲突时拒绝。SSE 的 PROGRESS 或 COMPLETE 均不独立构成成功证据。

成功必须证明原父目录不再有该 ID、目标目录有同一 ID，后代路径完整变更，全部文件 ID、名称、类型、MD5、大小及 SHA256 保持一致。部分结果逐项返回；单项冲突不代表未报告条目已经停止，无法证明的条目继续 unknown，保留锁并沿原号核对。每个条目均明确冲突且读回整棵子树未变化时返回 conflict，不覆盖并释放本次锁。

## 当前位置与审核历史

登记目录的父目录、一级分类、深度和路径按实际移动结果同步；移动目录的全部已登记后代同步。`governance_index` 和 `cards` 通过独立 `current_location` 字段登记当前位置。原 `folder_id`、`directory_snapshot`、metadata、审核 hash、审定正文及 R2 发布快照保留原值，以便旧事务和原证据仍可核对。

`card_routes` 表示下一版本的目标。历史文件移动不静默改变未来版本的审核分类；跨分类后新版本仍需一致的分类和合法目标。

## 正式启用门禁

正式库可先只读绑定，但执行必须等待同一账号在隔离库完成单文件往返及含至少四个目录层级和文件的整目录往返。四层按同一文件的真实祖先链计算，不以并列目录数量代替；回程必须恢复完整相对路径与父子关系。服务根据实际成功收据和内容清单登记 `file_roundtrip`、`folder_roundtrip`，同时绑定隔离库的 OpenAPI/native ID 与根目录指纹；更换绑定使旧验收失效，隔离库与正式库不得相同。客户端不能提交自证验收。连接状态的 `move_verified` 只在两项均通过后为真。真实云端验收前不报告正式移动可用。
