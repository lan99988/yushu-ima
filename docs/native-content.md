# 原生卡片内容维护（2.3.0）

## 实际能力与当前验收

同一私有 Site、App、插件继续使用原生密封会话及已核实的 formal/isolated 库绑定。真实移动不变。

- 已有 Markdown 原位编辑：**关闭**。2026-10-28 隔离样本真实调用 `file_manager/get_upload_credential_by_media` 返回 code=51，没有获得原对象上传凭据。官方静态客户端的 `replace_knowledge` 调用存在，但完整请求和同 ID 语义尚未证实。不能由接口名称或模拟测试推断原位替换可用。
- 编辑预览：核对原 ID、目录、完整原文字节 SHA-256，私有保存完整候选并返回原文/候选。`ima_edit_execute` 明确返回 unsupported，不调用上传、复制、删除或替换接口。
- 原生删除：实现 `knowledge_tab_writer/del_knowledge`，语义是**从指定知识库移除条目**，不是笔记标题墓碑。未证明物理媒体清除或原生回收站恢复。
- 正式库删除：服务端门禁要求同一账号、绑定及根目录指纹的隔离库成功删除、备份哈希和双 API 全库读回证据。部署或本地测试不构成验收。

## 工具

1. `ima_content_capabilities` 返回独立的编辑、删除状态，可对隔离媒体执行只读协议检查。检测结果只包含字段名、数字状态及对象键哈希，临时凭据不落盘、不进入工具输出。
2. `ima_delete_preview` 要求实际查询的单个 `media_id`、父 `folder_id` 和稳定 `request_id`。仅支持 1 MiB 以内 UTF-8 Markdown/TXT；文件夹与固定根不允许删除。
3. `ima_delete_execute` 要求同一请求号及服务返回的 `preview_hash`。用户授权须覆盖具体卡片；批量泛化授权不能定位目标。执行重新读取原文和位置，在私有 R2 备份原字节并读回校验，再派发一次原生请求。
4. `ima_delete_reconcile` 只读远端核对，并完成本服务的索引投影；绝不重发删除。`include_backup:true` 可读取备份原文。备份的可读取不等于已经支持恢复远端同 ID 条目。

## 一致性与失败

库级随机租约与已有上传的永久资源锁串行化本服务的移动、上传和删除，每次准备执行使用唯一资源锁 owner。`native_content_active` 将未知删除隔离，暂停同库写入。备份后在派发边界重新检查发布与迁移开关；该边界与管理端关闭/冻结动作共享全局租约。原生请求前写入 durable unknown；无论超时或响应丢失，都不能换号重试。

只有 native/OpenAPI 源目录均不含目标、双 API 完整扫描绑定库所有目录均无该 ID、备份 SHA-256 仍正确，才确认知识库移除。这只是当前状态证据；隔离库验收还必须具备本实现派发取得的原生逐项成功回执。嵌套状态码必须一致、类型正确，单文件回执必须只有一项且 ID 匹配；畸形或矛盾回执不作拒绝或验收证明。扫描不完整、目录漂移、迁移冻结、备份/索引失败，均保留原号待核对。明确拒绝且原文、身份与目录完整未变，可解除围栏；网络超时后原文件暂时仍在，不能认定未执行。

知识索引与卡片增加独立 `current_content.state=deleted_from_knowledge_base`，迟到的索引通过 `media_content_states` 投影。原审定原文、JSON、版本、证据、历史位置与发布快照保留，不能把旧审核当成新正文的审核。外部客户端并发修改无法获得提供方 CAS 保护，因此执行前最后一次读回后应避免人工同时操作同一文件。

## 验证记录

本地测试覆盖准确 JSON 协议、备份字节、旧证据保留、过期哈希、请求复用、超时前/后实际生效、拒绝、备份失败、禁止上传替代编辑。**真实云端删除验收须单独登记实际回执，不能填写模拟结果。**
