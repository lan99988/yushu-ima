# 从文章观点到有依据的知识判断

## 触发与交付

用户提交含可检验观点的文章、文字稿或讨论并要求整理、核实、补充入库时，默认执行本流程，无需再次粘贴提示词。医学、营养和其他经验科学的疗效、风险、机制及因果主张，使用研究论文核查。多篇材料先围绕同一知识对象整合，数量由独立主张决定，不固定三条、八条或每篇一张卡。

教程操作、法律政策、事件日期和个人经验保留各自适合的证据方法：操作看官方文档与实际验证，政策看正式原文，事件看一手记录，经验注明归属和情境。原样存档保留原件，不强行改造成论文审查。本流程提供事实判断，不产生额外写入授权。

ChatGPT网页会话使用宿主已有的检索/浏览能力读取论文，使用本插件云端工具保存与读回。无需本机脚本、WorkBuddy或另一个对话。论文是互联网发表的研究材料；“不用网络文章作证据”指不用新闻、科普、营销、社交帖子和AI回答代替研究本身。

## 1. 提取影响判断的独立观点

阅读全文，选出能被研究检验、会改变理解或行动的核心主张，合并重复表述。每项记录来源作者、原题、日期、可定位的段落/页码/时间戳，以及必要的短引文或忠实转述；保留人群、例外、前提和作者自己承认的适用条件。

把主张改写成明确问题：对谁，使用什么、多少、多久，与什么比较，期望改变什么结果。区分营养的生理作用、检测指标变化、实际功能改善和疾病事件；不要把它们合成一个笼统的“有效”。

事实断言、作者评价、个人经验分别标明。由助手新增的安全问题、反例或延伸问题标为“补充核查”，不能冒充作者原话或原文观点。原文存在前后矛盾时同时保留两处表述及定位，不能删掉作者的例外再反驳一个更强的说法。

完成条件：每个选定观点可追溯到实际材料，问题足够具体，作者立场未被改强或改弱。

## 2. 寻找并读取对应论文

先追溯原文所引论文，再检索与同一问题相关的独立研究、更新综述及相反结果。先按问题、研究对象与设计筛选，再比较结论；不预先站队搜支持材料，不以“最新”或“荟萃分析”标签自动判定质量更高。

优先阅读高质量系统综述/荟萃分析及直接回答问题的原始人体研究，特别是随机对照试验；观察性研究、动物/细胞实验和机制研究标明各自能回答的范围。核对作者、年份、题名、DOI/PMID或稳定链接，并留意更正、撤稿、研究重叠和综述检索截止日。无法确认的状态标待查，不凭未搜索到宣称不存在。

论文网站、期刊和文献数据库用于定位及读取研究。搜索摘要片段只作线索；读到论文正式发表摘要时标“摘要核对”，读到方法和结果正文时标“正文核对”，补充材料另行标明。未取得全文不声称逐项复核全文或图表。无法读到的论文保留待查，不能凭题名补造数据。

完成条件：每个判断对应可辨认的论文与实际读取位置；未找到、未读到或有争议的部分有明确记录。

## 3. 对照证据，主动检验反例

逐项核对研究设计、受试人群、样本量、制剂/干预、有效成分剂量、疗程、对照处理、主要与次要结果、效应大小和不确定范围，以及关键不良反应、偏倚、失访、资助及利益冲突中会改变解释的因素。不能把总鱼油重量写成EPA+DHA剂量，把总样本数写成某个子分析样本数，或把析因试验说成两个不同补剂互相比高下。

优先解释预先设定的主要结果，同时准确保留次要和亚组结果及其身份。区分绝对变化与相对变化、统计显著与读者实际可感受到的收益。没有显著差异不自动证明等效；没有证实获益不自动证明有害。指标升高、营养吸收或机制成立，不自动推出认知、症状、寿命或疾病结果改善。

保留阳性、阴性及分歧证据。检查不同人群、配方、剂量、对照和终点能否解释差异，分清实测结果与解释性推测。对照组改善不能直接证明对照物有疗效；也不能只比较不同试验就断言某个成分造成结果差异。更窄的样本、更新的小综述或选择性引用不能代表整个证据库。

完成条件：来源主张与论文结果按同一问题比较；关键反例、适用条件和证据缺口不会被省略。

## 4. 明确判断，白话解释

根据证据主动下判断，可用“支持”“部分支持”“不支持/原文推论过头”“证据不足”或“研究结果有分歧”。这些是判断含义，不是要求所有卡片机械列五个标签。立场鲜明指把判断与理由说清，不等于情绪攻击、强行二选一、替作者辩护或为某种产品制造优势。

推荐句式：**判断 → 最关键的论文结果 → 适用条件/为何原推论需要修正 → 对读者的实际含义。** 例如：“不支持健康人为普遍补脑承诺常规购买；总体试验未确立稳定的认知收益”，不要扩大成“所有年龄、所有情形都已证明完全无效”。这只是表达范式，不是所有补剂或新研究的预设结论。

开篇点明主题并直接给最重要的答案，结论数量服从内容。专业术语首次就地解释；每段先判断后依据。必要风险和不确定性只在相关处准确说明，删去写作过程汇报、假想对手、辱骂、泛泛辩解和反复免责。证据不足就明确写不足，不用含糊的“各有道理”掩盖判断。

完成条件：只读开头即可知道核心答案；每个强判断有相称证据，来源立场与助手判断清楚区分。

## 5. 整合到同一主卡并核验

先按主卡规则双检索并读取现卡，按目录规则实时扫描和选择目录。已有对象将新判断、必要解释和旧有重要内容整合为完整正文；不同角度放同卡小节，不按篇数、观点数或证据数量建重复卡，也不只在末尾追加核查补丁。

读者看到的是结论先行的完整文章。按需要使用“原文观点｜论文结果｜本卡判断”表或自然段，长文的细节放到对应小节；表格不是固定模板。参考文献给真实题名、作者/研究组、年份和DOI/PMID/链接。来源原件分别保全；若使用来源包，明确包的性质，保留可分离的逐篇完整快照、来源信息和独立哈希，不能把拼接稿冒充某一篇原文。相关图片的读取、选择、原图和译文继续遵守独立图片规范，文字核查不冒充图片或重开验收。

正文只保留可读证据与参考文献，内部JSON、哈希、编号、版本和录入流水留后台。后台逐项证据记录应含原文定位、论文标识、实际读取范围/时间、支持或反驳的具体判断及局限，并绑定本次完整正文。仅摘要核对、部分主张核查和语言修改都不能自动提升整卡核查状态。按实际工具契约提交证据；入口无法表达部分核查时，将范围写入可追溯材料和必要正文说明，整卡保留待核查，不伪造全卡web_verified。

按主卡规则的新建/更新分流、真实授权、预览和原请求恢复流程执行。只有成功收据、完整正文读回、正确目录、备份、旧可见版本替换与索引同步，以及仅一张当前主卡都核验后，才报告完成。保存成功与论文核查范围分别报告；没有本轮依据时不宣称已完成ChatGPT网页界面端到端验收。

完成条件：论点、证据和判断已进入正确的唯一主卡，来源可追溯，正文可读，保存状态与核查状态均如实报告。
